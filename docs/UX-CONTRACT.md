# 공통 UI 동작

사용자 요구사항과 현재 프론트엔드 예시 데이터 계약을 기준으로 한다. 시각 기준은 [DESIGN.md](DESIGN.md), 예시 데이터 범위는 [README.md](../README.md) 및 [src/data/index.js](../src/data/index.js)가 소유한다.

2026-10-06 전체 UI 정리: ui-system.css가 공통 버튼·선택·본문·패널 표현을 소유한다. 홍보 문구와 장식용 아이콘/그림 대신 구체적 조작 안내를 사용하며 예시 정보는 계속 구분한다. AI 안내와 Google 전송 고지는 유지한다. 전체 후보·비용 details는 기본 접힘이며 개수·유사 제외 수를 제목에 표시하고 펼치면 기존 목록 전체를 유지한다. 지도 안내의 출발 위치 버튼은 자동 선택/직접 지정/지도 중심으로 짧게 표시하되 접근성 이름에 기능을 명시한다. 조건·지도 선택·검색·오류 복구·모바일 전환은 기존 상태 소유자와 취소 규칙을 유지한다.

## 상태 유지

지역 검색·탭 이동·검색어 삭제 시 거리와 난이도를 유지한다. 현재 조건 및 선택은 페이지 내부 상태이며 새로고침하면 초기화된다. 프로토타입에 URL 상태 공유는 아직 제공하지 않는다.

## 데이터와 오류

기존 지역 카드의 예시 경로는 도로를 따라 계산한 실제 경로가 아니다. 지도 위 실제 LINK 후보와 구분한다. 점수·거리·시간·지표는 예시 생성 결과이며 실제 주행 가능성을 판정하지 않는다. 미지원 검색에는 지원 예시와 수정 방향을 보여준다. 검색어 지우기는 오래된 오류와 결과도 함께 지운다. 실제 도로 후보의 명시적 AI 맞춤 추천은 Gemini 서버 API를 사용하며 예시 코스는 제외한다. 실제 도로 검색의 debounce·취소·페이지 조회는 아래 검색 확장 계약을 따른다.

## 검증

정적 감사는 접근성의 완전한 증명이 아니다. 브라우저에서 모바일 패널 폭, 팝업 충돌, 목록 스크롤, 키보드, 모달 포커스, 검색 성공·실패와 지도 표시를 확인한다.



## 실제 도로 검색 계약

- Header / road-search: 입력 300ms 후 검색, IME 조합 중 요청·제출 방지, 명시적 검색은 즉시 실행. 네이티브 입력과 결과 버튼을 사용하며 Tab/Enter, 입력의 ArrowDown, 결과의 ArrowUp/Down, Escape 닫기와 포커스 복원을 지원한다.
- 검색은 정확한 도로명 우선, 부분 일치를 포함한다. 한 번에 도로명 8개에 해당하는 metadata shard만 읽고 결과 20개씩 더 보기로 제공한다. 같은 이름의 모든 그룹은 추가 조회로 접근할 수 있다.
- query·선택·열림 상태는 구분한다. superseded 요청은 취소하며, 늦은 응답은 현재 query/선택을 덮어쓰지 않는다. 지우기는 검색·geometry 요청과 선택을 취소한다. 상태는 기존 프로토타입과 동일하게 페이지 내부에서 유지하며 URL에 저장하지 않는다.
- geometry는 선택한 그룹의 shard만 읽으며 실패 시 이전 선택을 유지하고 재시도한다. 모바일 지도 화면에도 로딩·실패·재시도 상태를 노출한다.
- MainPage / RoadInfo: 실제 도로를 선택하면 mock 코스 대신 도로 정보를 보여주고 모바일은 지도 보기로 이동한다. 기존 예시 지역을 선택하면 원래 코스 흐름으로 복귀한다. 거리·난이도 조건을 유지한다.
- NaverMapView / LeafletMapView: bounds로 확대하고 모든 LINK를 강조한다. 네이버는 기존 확장된 raster render 면적을 고려하는 getNaverCourseViewport를 사용한다. Leaflet은 flyToBounds/fitBounds를 사용한다. 클릭/hover 정보는 DOM textContent로 만들어 원본 도로명이 HTML로 실행되지 않는다.
- RoadLink.linkId / selectedLinkIds: 문자열 ID를 그대로 유지한다. 미수집 점수·교통량·사고·유동인구는 null이다. 도로 그룹은 표시 단위이며 실제 주행 가능한 route와 구분한다.

## 지도 차로 필터 계약

- 원본 데이터와 범위: scripts/preprocess-lane-tiles.py가 MOCT_LINK SHP/DBF/PRJ를 읽고 이름 없는 구간도 포함한다. 도로명 검색용 그룹과 독립된 공간 타일이며 LINK_ID는 원본 문자열 그대로다. 차로 구분은 원본 LANES 값이며 왕복 합계나 추천 난이도로 재해석하지 않는다.
- MainPage / LaneFilter: 초기 선택 없음, 1~6 및 7 이상을 복수 선택하고 재클릭 또는 해제로 제거한다. 차로는 표시 필터가 아닌 후보 생성의 선호 조건이다. 미선택 차로를 제외하지 않고 길이 × 3의 비용을 가산한다. 모두 해제하면 기본 비용 기준을 사용한다. 지역/검색/탭 전환과 독립해 유지하고 버튼만 누를 때 모바일 패널을 전환하지 않는다.
- useLaneRoads / lane-roads: 줌 13 이상에서 현재 보이는 범위의 z12 정적 gzip 타일만 전체 차로로 읽는다. 200ms 후 요청하고 지도 이동/언마운트 시 이전 요청을 취소한다. 선호 차로 변경으로 다시 읽지 않는다. 최대 6개 요청 병렬, 캐시 128개, 타일 경계에서 LINK_ID 중복 제거. 범위 128타일 또는 결과 12,000 LINK 초과 시 일부만 사용하지 않고 확대 안내한다.
- laneRenderBatch: 네이버의 선택 후보 빨간 경로를 MessageChannel 작업당 한 구간씩 생성한다. 후보 변경/언마운트 시 남은 작업과 이전 경로를 정리한다. 전체 차로의 파란 도로선과 incrementalLaneLayer는 현재 지도 흐름에서 사용하지 않는다.
- LaneRoadStatus: 차로 안내창에 현재 배율을 함께 표시한다. 네이버는 CSS 반 단계 확대를 반영한 표시 배율을 사용하며 Leaflet은 실제 지도 줌 값을 사용한다. 소수 한 자리까지 표시하고 정수의 불필요한 .0은 생략한다.
- ConnectedCourseControl: MainPage의 distanceRange가 거리의 단일 소유자다. 차로 미선택이어도 줌 13 이상/현재 범위 조회 완료 때 후보 찾기 버튼을 활성화한다. 자동 모드는 현재 화면을 4×4 구역으로 나누고 각 구역 중심과 가까운 시작 노드 최대 3개씩(총 48개)을 비교한다. 직접 지정 모드는 선택 좌표의 300m 안 가장 가까운 원본 시작 노드 하나를 사용한다. 전체 차로의 F_NODE→T_NODE로 경로를 연결한다. 지도 위치만 바뀌면 이전 생성 경로는 유지하며 버튼으로 현재 범위에서 다시 생성한다. 거리/선호 차로/사용자 조건/경로 형태가 바뀌면 생성 경로와 진행 중 Worker/AI 요청을 정리한다. 계산 실패는 이전 결과를 보존하고 오류를 안내한다. 순환/편도는 DifficultyControl과 같은 버튼 선택 패턴이며 locale은 한국어다.
- connected-course: 정적 LINK 부분 그래프만 사용한다. LineString의 구면 거리 합계를 미터로 계산하며 결과 합계가 min/max 안일 때만 반환한다. 방향을 뒤집거나 좌표 교차로 연결을 추측하지 않는다. 불연속 multipart는 제외하며 이음 좌표 간격 60m 초과 경로는 배제한다. 순환 경로는 귀환 시 출발 경로의 내부 노드 재사용을 금지한다. 자동 최대 48개 시작점 또는 직접 지정한 1개 시작점/각 64개 반환 후보를 탐색하며 no-match는 해당 제한과 현재 화면 범위의 결과다. 전체 전국 최적 경로 또는 실제 통행 가능성을 보장하지 않는다. 계산은 Worker로 분리하여 지도 조작을 막지 않는다.
- 두 지도 제공자: 선택 후보만 빨강으로 표시하며 실제 후보가 있으면 기존 예시/검색 경로와 예시 선택 카드를 숨겨 혼동을 피한다. 후보를 지우면 원래 검색/예시 표시로 돌아온다. 후보 생성·AI 선택은 지도 중심을 바꾸지 않는다. 네이버는 확대 raster 화면을 고려해 실제 보이는 bounds로 조회한다.
- 다중 연결 추천: 희망 거리 전체 범위에서 다익스트라 기반 순환/편도 후보를 탐색한다. 발견한 유효 후보를 총 cost 오름차순으로 정렬하고 3·4·5개 채택 버튼으로 상위 후보 수를 선택한다(기본 3). 기존 거리대별 한 개 선택은 현재 화면에서 사용하지 않는다. 동일 LINK 집합 중복은 제거하고, 총 cost 순으로 기존 유지 후보와 경로 일치율 90% 이상이면 유사 제외한다. 일치율은 같은 방향의 공통 LINK geometry 길이 합계 / 두 경로 중 긴 경로의 geometry 길이 합계다. 실제 경로 순서나 출발 노드가 달라도 같은 LINK는 공통으로 계산한다. 제외 뒤 다음 후보로 채택 수를 채우며 충분한 후보가 없으면 찾은 수만 채택한다. 90% 미만 중첩은 허용한다. 개발용 전체 후보 목록은 유사 제외 후 유지된 후보의 거리, 총 cost, km당 cost, 차로/선호/회전/교통/사고 비용을 표시하고 미채택 후보도 지도에서 선택할 수 있다. 채택한 경로를 모두 빨강으로 표시하고 선택 경로는 opacity 1·7px, 다른 경로는 opacity 0.28·5px로 표시한다. 지도 선 클릭과 후보 버튼은 동일한 선택 상태를 갱신한다. 키보드 Enter와 aria-pressed를 지원한다. 비용은 안전 점수가 아니며 짧은 코스가 유리할 수 있음을 표시한다.
- DistanceControl: 최소 허용 거리 5km, 최대 30km, 최소·최대 차이는 10km 이하다. 최대를 늘려 폭이 10km를 넘으면 최소를 최대-10으로 이동한다. 최소를 줄여 폭이 10km를 넘으면 최대를 최소+10으로 이동한다. 조절점 순서가 뒤집히면 다른 조절점을 같은 값으로 맞춘다. 숫자 입력과 슬라이더는 distance-range.js의 updateDistanceRange를 공유하며 입력은 정수 km다.
- LaneRoadStatus: 준비/확대 필요/불러오는 중/성공 건수/빈 결과/오류 및 재시도. 바뀐 조건의 이전 선을 즉시 제거하고 늦은 응답이 다시 그리지 못하게 한다.

- 경로 비용: 원본 LANES별 길이 비용 배수는 3/4/5=1, 2/6=1.5, 7=2, 8 이상=2.5, 1 또는 미확인=3이다. 실제 거리는 geometry 미터 합계이며 비용과 분리한다. 진입/진출 도로의 교차점 인근 방위각 차이로 직진(<30도)=0, 우회전=50, 좌회전=150, 유턴(절댓값 150도 이상)=500의 회전 비용을 가산한다. 회전 비용은 실제 주행거리 미터가 아닌 비교용 비용 단위다. 중복 좌표는 건너뛰며 시작 시 회전과 주행 종료 뒤의 가상 회전은 계산하지 않는다. 귀환 경로 탐색에는 출발 경로의 마지막 LINK를 전달해 접합 회전도 반영한다.
- 비용 탐색 상태: 다익스트라 우선순위는 누적 비용이다. 현재 노드와 진입 LINK마다 비용/거리의 비지배 상태를 최대 8개 유지한다(저비용 7개와 최단 거리 상태). 자동 출발점 최대 48개(지도 범위 없는 호환 API는 중심 근처 8개), 시작점당 편도 128개/순환 64개 후보 제한 안에서 검증된 후보 모두를 수집하고 비용순으로 정렬한다. 가장 싼 후보보다 비싸다는 이유로 탐색을 중단하지 않는다. 더 짧고 비싼 경로도 유지해 저비용 우회가 거리 상한을 초과할 때 대안을 찾는다. 역방향 탐색은 회전 비용 없는 하한으로만 사용한다. 반복 LINK는 배제한다. 상태 수와 후보 제한 때문에 전역 최적 경로를 보장하지 않는다. 실제 교통량·사고 자료 연동은 아직 없으며 통행 제한·보호구역은 비용에 반영하지 않는다.
- 미래 교통량/사고 비용: road-data-cost.js가 선택 차로 LINK의 trafficVolume/LANES와 accidentCount/km를 비교 가능한 집단의 기준으로 정규화해 길이 비례 비용을 가산한다. 자세한 입력 계약은 ROAD-COST-DATA.md를 따른다. 관측값·양수 기준·동일 기간이 있어야 반영하며 없으면 점수 null/추가 비용 0으로 기존 경로 비용을 유지한다. 실제 0과 미관측은 구분하고 costBreakdown/dataCoverage를 제공한다. 현재 실데이터 연동은 없고 사용자 화면에 가짜 지표나 비용 수식을 표시하지 않는다.

## Gemini 맞춤 추천 계약

### 비용 기반 난이도 추천 (2026-10-06)

아래 규칙은 이전의 저비용 상위 3·4·5개 채택 규칙을 대체한다. 탐색·90% 유사 제외 후 유지된 후보의 총 cost 최솟값(min)·최댓값(max)을 구하고 중간값은 (min+max)/2다. min~max를 3등분해 하위 구간 쉬움, 중간 구간 보통, 상위 구간 어려움으로 표시한다. 동일 비용은 모두 쉬움으로 표시하며 가짜 난이도를 만들지 않는다. 실제 운전 부담이나 안전도 검증값이 아닌 현재 후보 풀 안의 상대 구분이다.

단일 난이도는 min/중간값/max에 가까운 해당 구간 후보부터 기본 4개(3개 선택 가능)를 채택한다. 해당 구간이 부족하면 남은 후보를 총 cost 내림차순으로 보충한다. 전체는 난이도별 2개씩, 최대 6개를 번갈아 채택하며 부족하면 남은 후보 중 cost가 높은 순서로 6개까지 보충한다. 실제 난이도와 대체 여부를 버튼에 표시한다. 두 경우 모두 채택 후보 사이 50% 미만 일치율과 원래 거리 범위를 유지하며, 그래도 부족하면 실제 수만 표시한다. 전체 비용 목록에는 난이도와 min/중간/max를 제공한다.

희망 난이도는 MainPage → 두 지도 → ConnectedCourseControl로 전달한다. 난이도/채택 수 변경은 이미 탐색된 풀에서 즉시 다시 선택하고 AI 요청·결과를 취소한다. 지도를 이동하거나 도로를 재조회하지 않는다. 선택 경로와 지도 후보를 동기화한다. Gemini에는 최대 6개, 희망 난이도, 후보별 실제 difficulty 및 difficultyFallback을 전달하며 원래 후보 번호는 유지한다. API의 candidate_1~6은 채택 순서에 대응한다.

- DriverPreferences가 연습 목표 버튼 목록을 소유하며 MainPage의 driverProfile이 단일 상태다. 우회전(right)·교차로(junctions)·좌회전(left)·유턴(uturn)·좁은 도로(narrow) 5개를 profile.goals 배열로 관리하며 모두 복수 토글이다. 부담 적은 주행은 제거한다. 기본은 미선택이며 모든 항목은 재클릭으로 개별 해제한다. 기존 좌회전·유턴·좁은 도로 비용 가산은 유지하고 AI에는 전체 선택 목록을 전달한다. 운전 경험을 받거나 API에 전달하지 않는다. 설정은 페이지 내부에서만 유지한다.
- ConnectedCourseControl은 실제 후보 생성 후 명시적 AI 맞춤 추천 버튼을 제공한다. 조건과 후보 요약의 Google Gemini 전달을 알리고 중복 요청을 차단한다. 버튼 폭을 유지하고 진행 중임을 알린다. 입력 실패/키 누락/API 오류/시간 초과/출력 검증 실패 시 후보와 입력을 보존하고 수동 재시도를 제공한다.
- course-recommendation이 geometry 특징 계산과 검증된 근거 설명을 소유한다. Gemini는 기존 후보 ID와 허용된 근거 코드만 반환한다. 없는 데이터 근거·중복/새 후보는 거부한다. 교통량·사고 비교는 모든 후보의 전체 구간 관측과 동일 기간이 필요하다. 원본 길이·회전·선호 차로 비율의 사실만 설명하며 안전 확률을 표시하지 않는다.
- 총 cost 순 후보 번호는 유지한다. AI에는 채택한 최대 5개만 전달한다. AI 추천 표시와 우선 선택을 제공하며 사용자는 다른 후보를 선택할 수 있다. 조건 변경·지우기·언마운트는 요청을 취소하고 늦은 결과를 무시한다. 자세한 서버/API 계약과 설정·검증은 GEMINI-COURSE-RECOMMENDATION.md가 소유한다.

- 지도 시점: 희망 거리/난이도/선호 조건 변경은 코스와 오버레이만 갱신하며 지도 중심·배율을 유지한다. 자동 이동은 지도 준비, 지역 선택/홈 복귀, 다른 예시 코스 묶음 요청(routeBatch), 순위 탭 전환, 검색 도로/행정구역 선택에만 반응한다. 전체 코스 보기 버튼의 명시적 재정렬은 유지한다. routes 배열의 변경을 자동 시점 이동 신호로 사용하지 않는다.

거리 변경 시점 회귀 검증(2026-10-06): 네이버/Leaflet 모두 지역 미선택 상태의 7.5 배율과 마포구의 14 배율을 거리 숫자 입력·슬라이더 변경 뒤 유지했다. 5~12km → 최대 20km 입력 → 최소 슬라이더 ArrowRight로 11~20km가 되어도 배율 14 및 지도 타일이 유지됨. 네이버 전체 코스 보기 버튼은 배율 12로 정상 재정렬. 프로덕션 빌드와 UI 정적 감사 통과. 증거: .local/screenshots/distance-keeps-zoom.png.

- 출발 위치: 기본 자동 선택. 지도에서 지정 버튼을 누른 뒤 지도를 클릭하거나 지도 중심으로 지정 버튼을 사용한다. 지정 취소는 이전 선택을 유지하며 자동 선택은 지정 좌표를 지운다. 지정 좌표는 파란 원으로 표시하고 실제 코스 출발 노드는 별도 출발 마커로 표시한다. 가까운 도로 노드가 없으면 오류를 표시하고 자동 출발점으로 대체하지 않는다. 지정 위치→노드의 접근 거리는 안내용 직선 거리이며 코스에 포함하지 않는다. 출발 위치 변경은 Worker/AI와 이전 후보를 정리하고 지도를 이동시키지 않는다. 거리·선호 변경 및 지도 이동은 지정 좌표를 유지하며 지역/도로/순위 맥락 변경은 지운다. 수동 후보는 모두 동일 시작 노드이며 자동 후보는 서로 다른 시작점을 가질 수 있다. 비용 비교는 발견 후보 범위 안에서만 보장한다.

- 유사 후보: Worker가 전체 발견 후보를 분류하고 UI는 개발 목록 제목에 전체 발견 개수와 유사 제외 개수를 함께 표시한다. 유사 제외 후보는 개발 목록에서 숨기고 채택 버튼/AI 입력에도 포함하지 않는다. 후보 번호는 전체 cost 순 번호를 유지하며 Gemini 식별자는 채택 순서의 candidate_1~5로 재매핑하고 응답도 원본 후보 인덱스로 복원한다. 그리디 비교는 실제 유지한 대표 후보에 대해서만 수행하며 전이적 유사도 묶음으로 합치지 않는다.

- 채택 후보 다양성: 전체 목록의 90% 유사 제외와 별개로, Worker는 cost 순 유지 후보 중 이미 채택한 모든 후보와 일치율이 50% 미만인 경로만 최대 5개 선정한다. 같은 방향의 공통 LINK 길이 / 긴 경로 길이를 사용하며 정확히 50%도 제외한다. 채택 수 3/4/5는 이 목록의 앞부분을 사용한다. 부족한 경우 기준을 완화하지 않고 실제 채택 개수를 표시한다. 50~90% 중첩 후보는 개발 전체 목록에서 검토할 수 있으나 채택 버튼과 Gemini 입력에는 포함되지 않는다.

- 순환 복귀 선호: 복귀 다익스트라는 연습 목표의 유턴 항목을 선택한 경우에만 출발 경로와 동일 노드 쌍을 역방향으로 연결하는 LINK에 길이(m)×3의 추가 cost를 적용한다. 미선택 시 이 추가 비용은 0이며 기본 유턴 회전 비용은 유지한다. LINK ID나 도로명 일치에 의존하지 않는다. 추가 비용은 costBreakdown.preference에 포함하고 실제 geometry 거리에는 가산하지 않는다. 회전 cost와 50% 채택 다양성 조건은 유지한다. 다른 복귀 경로가 없으면 왕복 후보도 허용한다. 원본 edge를 수정하지 않고 검색별 비용만 기록한다. 같은 노드 쌍을 잇는 별도 도로도 역방향 구간으로 취급할 수 있고 노드가 분리된 맞은편 차도는 감지하지 못하므로, 실제 동일 도로를 보장하는 판정은 아니다.

- 지도 후보 선택: ConnectedCourseControl의 후보 풀과 부모 MapView의 선택 코스를 단일 선택 상태로 연결한다. 채택 수 변경·경로 지우기·조건 변경·언마운트 시 지도 후보도 함께 갱신하거나 제거한다. 개발 목록에서 미채택 후보를 고르면 채택 후보와 선택한 추가 후보만 표시한다. 선택 경로를 가장 위에 그리며 겹친 구간에서는 선택 경로가 클릭을 받는다. 지도에서 고르는 행동은 카메라를 이동하지 않는다. 출발 위치 지정 중에는 후보 선택을 하지 않는다. Naver는 선을 배치 생성하고 선 선택은 기존 선 스타일만 갱신한다.

지도 후보 선택 검증(2026-10-06): 네이버 실제 후보 382개 중 채택 1/3/4에서 반투명 선 클릭 후 후보3·5.01km로 동기화했다. Leaflet 실제 후보 349개 중 채택 1/5/6에서 지도 선 클릭 후 후보6·5.06km, 버튼 클릭 후 후보5·5.25km로 동기화했다. Leaflet 선택 선 77개 opacity 1, 비선택 선 136개 opacity 0.28을 확인했고 두 지도 모두 경로 지우기 후 코스 선이 0개였다. 증거: .local/screenshots/map-candidate-selection.png.

- 줌 입력(2026-10-06 변경): 네이버와 Leaflet의 확대/축소 버튼 및 휠은 정수 1단계 간격이다. Leaflet zoomSnap/zoomDelta=1, 네이버 change는 현재 배율을 정수로 정렬한 뒤 ±1을 적용한다. 자동 지역 이동 애니메이션의 중간 배율은 연속적으로 변할 수 있으나 도착 배율은 정수다. 최소 7·최대 17은 유지한다.

- LaneRoadStatus 접기: 오른쪽 위 − 버튼으로 현재 배율을 남긴 작은 안내창으로 접고 + 버튼으로 다시 펼친다. 네이티브 버튼은 aria-expanded/aria-controls와 접기·펼치기 이름을 제공한다. 본문은 hidden 속성으로만 숨겨 ConnectedCourseControl을 언마운트하지 않으며 Worker·AI 요청·후보 선택·출발 위치·지도 경로를 보존한다. 접힌 상태의 숨긴 입력은 키보드 탭 탐색에서도 제외한다. 도로 불러오기 상태가 바뀌어도 사용자가 정한 접힘 상태를 유지한다.

## 연습 목표 우선 추천 (2026-10-06)
- 다섯 목표는 회피 조건이 아닌 연습 대상이다. 선택한 우회전·좌회전·유턴 회전 비용은 70% 할인한다. 1차로 구간은 기본 차로 비용 25% 할인, 교차로 추정 노드 출발 구간은 기본 차로 비용 15% 할인한다. 여러 할인을 합산해도 도로 비용은 양수로 유지한다. 교통·사고 비용과 물리적 거리는 할인하지 않는다.
- 교차로는 현재 로드 그래프에서 서로 다른 인접 노드가 3개 이상인 노드로 추정한다. 단순 직진 연결과 양방향 LINK 두 개를 교차로로 세지 않는다. 차로 수가 누락된 구간은 좁은 도로 보너스에서 제외한다.
- 후보 비용으로 난이도를 나눈 뒤, 같은 난이도 안에서는 충족한 목표 종류 수가 많은 후보부터 추천한다. 그 다음 기존 최소/중간/최대 비용 기준을 적용한다. 전체 6개와 단일 난이도 최대 4개, 중복 50% 제외 조건을 유지한다. 목표가 없으면 기존 추천 순서다.
- 저장된 서울 코스도 목표 충족 수와 목표 할인 비용으로 정렬한다. 저장 코스 난이도는 최초 생성 시 상대 구분을 유지한다.
- Gemini에는 실제 추정 교차로 횟수를 전달하고 선택 목표 포함 우선 원칙을 적용한다. 유턴 선택 시 기존 동일 길 복귀에 대한 별도 비용은 유지한다.


## 희망 지역·지역 이동·코스 저장 (2026-10-06)
- 기존 지역별 순위 탭을 희망 지역 탭으로 교체한다. 전국 자료에 등록된 지역을 시·도 버튼 → 시·군·구 버튼 순서로 선택한다. 시·도만 바꾸면 지도와 추천 조건을 유지하며 시·군·구를 눌렀을 때 적용한다. 출발 지역 선택 뒤 선택 사항인 도착 지역을 지정할 수 있다. 같은 지역은 도착 지역 선택에서 제외한다.
- 지역 선택은 지도 시점을 이동한다. 탭만 변경할 때 지도 시점과 추천 상태를 초기화하지 않는다. 선택 조건은 거리·목표·난이도와 독립적으로 유지한다.
- 출발 노드는 현재 탐색 범위와 출발 지역 자료의 bounding box 교집합과 실제 행정구역 폴리곤 안에서 선택한다. 도착 지역이 있으면 편도만 허용하고, 경로 끝 노드가 도착 지역 bounding box와 폴리곤에 포함된 후보만 추천한다. 경계 원본은 기존 SGIS 기반 2026-07-01 자료이며 약 1m로 형상을 단순화했다. 신호 통제는 검증하지 않는다.
- 지역 이동은 두 지역 중심을 포함한 제한된 도로 범위를 로딩하여 현재 화면 배율과 독립적으로 탐색한다. 임의 직선 경로를 만들지 않으며, 희망 거리 또는 제공 도로 범위에서 연결되지 않으면 후보 없음/범위 확대 안내를 표시한다.
- 추천 카드 및 계산된 후보의 코스 저장 버튼으로 저장한다. 저장 코스 탭에서 다시 열면 저장 당시 형상·거리·비용·난이도·순환/편도를 유지하고 해당 경로로 지도 이동한다. 편도는 출발과 도착을 따로 표시한다.
- localStorage 키 beginner-driving.saved-courses.v1, 최대 30개. 동일 LINK 집합 중복 저장을 막는다. 오류/용량 부족은 실패 문구를 표시하고 기존 데이터를 보존한다. 사용자 기기 간 동기화와 서버 캐시는 포함하지 않는다.
- 테스트: 지역 출발/도착 제한, 순환에서 도착 지역 거부, 연결 불가 지역, 저장/재열기/중복/삭제/손상 데이터/용량 실패 검증.

실제 UI 검증: 전국 256개 지역 검색, 서울 마포구→서대문구 폴리곤 조건으로 3,784개 후보/6개 추천, 5.01km 편도 저장·재열기, 출발·도착 별도 표시 확인. 순환 저장 코스는 새로고침 후 재열기 확인.

희망 지역을 고르면 지도 배율과 이동에 관계없이 지역 중심의 제한된 도로 범위를 로딩한다. 지역 미선택 시 기존 배율 13 조건을 유지한다. 출발·도착 지역이 지정된 편도는 A* 우선순위(누적 비용 + 도착 노드 집합까지의 비용 하한)를 사용하며 최대 거리 내 도달 불가능한 상태를 제외한다. 실제 비용 할인 이후 최소 비용/미터와 구면 현 거리 하한을 사용하고 회전 비용은 하한에 추가하지 않는다. 순환은 기존 탐색을 유지한다. 후보 다양성과 거리 조건 때문에 여러 상태를 탐색하며, 기존 노드별 상태/후보 수 제한이 있어 전국 전역의 최적성은 보장하지 않는다.

지역 이동 거리 (2026-10-07): 지역 이동을 포함해 모든 코스의 희망 거리는 5~30km, 최소·최대 차이는 10km 이내다. 지역을 선택한 상태에서 시·도 버튼을 누르면 해당 시·도 경계를 화면에 맞춰 이동하고, 출발/도착 시·군·구 선택 영역은 각각 파랑/초록 윤곽과 옅은 채움으로 지도에 표시한다. 최대 세 지역을 선택 순서대로 연결한다. 출발 구역에서 시작해 선택된 중간 구역을 실제로 경유하고 마지막 구역 안에서 끝나는 편도 경로를 탐색한다. 선택하지 않은 구역은 추천 지역이 아니다. 시·군·구 아래의 기본 안내/개수 문구는 표시하지 않는다.
