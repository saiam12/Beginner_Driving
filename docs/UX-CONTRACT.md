# 공통 UI 동작

사용자 요구사항과 현재 프론트엔드 예시 데이터 계약을 기준으로 한다. 시각 기준은 [DESIGN.md](DESIGN.md), 예시 데이터 범위는 [README.md](../README.md) 및 [src/data/index.js](../src/data/index.js)가 소유한다.

## 상태 유지

지역 검색·탭 이동·검색어 삭제 시 거리와 난이도를 유지한다. 현재 조건 및 선택은 페이지 내부 상태이며 새로고침하면 초기화된다. 프로토타입에 URL 상태 공유는 아직 제공하지 않는다.

## 데이터와 오류

현재 경로는 도로를 따라 계산한 실제 경로가 아니다. 점수·거리·시간·지표는 예시 생성 결과이며 실제 주행 가능성을 판정하지 않는다. 미지원 검색에는 지원 예시와 수정 방향을 보여준다. 검색어 지우기는 오래된 오류와 결과도 함께 지운다. 추천 알고리즘의 외부 요청은 아직 없다. 실제 도로 검색의 debounce·취소·페이지 조회는 아래 검색 확장 계약을 따른다.

## 검증

정적 감사는 접근성의 완전한 증명이 아니다. 브라우저에서 모바일 패널 폭, 팝업 충돌, 목록 스크롤, 키보드, 모달 포커스, 검색 성공·실패와 지도 표시를 확인한다.



## 실제 도로 검색 계약

- Header / road-search: 입력 300ms 후 검색, IME 조합 중 요청·제출 방지, 명시적 검색은 즉시 실행. 네이티브 입력과 결과 버튼을 사용하며 Tab/Enter, 입력의 ArrowDown, 결과의 ArrowUp/Down, Escape 닫기와 포커스 복원을 지원한다.
- 검색은 정확한 도로명 우선, 부분 일치를 포함한다. 한 번에 도로명 8개에 해당하는 metadata shard만 읽고 결과 20개씩 더 보기로 제공한다. 같은 이름의 모든 그룹은 추가 조회로 접근할 수 있다.
- query·선택·열림 상태는 구분한다. superseded 요청은 취소하며, 늦은 응답은 현재 query/선택을 덮어쓰지 않는다. 지우기는 검색·geometry 요청과 선택을 취소한다. 상태는 기존 프로토타입과 동일하게 페이지 내부에서 유지하며 URL에 저장하지 않는다.
- geometry는 선택한 그룹의 shard만 읽으며 실패 시 이전 선택을 유지하고 재시도한다. 모바일 지도 화면에도 로딩·실패·재시도 상태를 노출한다.
- MainPage / RoadInfo: 실제 도로를 선택하면 mock 코스 대신 도로 정보를 보여주고 모바일은 지도 보기로 이동한다. 기존 예시 지역을 선택하면 원래 코스 흐름으로 복귀한다. 거리·난이도 조건을 유지한다.
- NaverMapView / LeafletMapView: bounds로 확대하고 모든 LINK를 강조한다. 네이버는 기존 확장된 raster render 면적을 고려하는 getNaverCourseViewport를 사용한다. Leaflet은 flyToBounds/fitBounds를 사용한다. 클릭/hover 정보는 DOM textContent로 만들어 원본 도로명이 HTML로 실행되지 않는다.
- RoadLink.linkId / selectedLinkIds: 문자열 ID를 그대로 유지한다. 미수집 점수·교통량·사고·유동인구는 null이다. 도로 그룹은 표시 단위이며 실제 주행 가능한 route와 구분한다.

## 지도 차로 필터 계약

- 원본 데이터와 범위: scripts/preprocess-lane-tiles.py가 MOCT_LINK SHP/DBF/PRJ를 읽고 이름 없는 구간도 포함한다. 도로명 검색용 그룹과 독립된 공간 타일이며 LINK_ID는 원본 문자열 그대로다. 차로 구분은 원본 LANES 값이며 왕복 합계나 추천 난이도로 재해석하지 않는다.
- MainPage / LaneFilter: 초기 선택 없음, 1~6 및 7 이상을 복수 선택하고 재클릭 또는 해제로 제거한다. 선택은 기존 지역/검색/탭 전환과 독립해 유지하고 모바일 선택 시 지도 보기를 연다. 상태는 기존 프로토타입처럼 페이지 내부에 유지한다.
- useLaneRoads / lane-roads: 줌 13 이상에서 현재 보이는 범위의 z12 정적 gzip 타일만 읽는다. 200ms 후 요청하고 지도 이동/차로 변경/언마운트 시 이전 요청을 취소한다. 최대 6개 요청 병렬, 캐시 128개, 타일 경계에서 LINK_ID 중복 제거. 범위 128타일 또는 결과 12,000 LINK 초과 시 일부만 표시하지 않고 확대 안내한다. 알 수 없는 차로 수는 선택 범주에 넣지 않는다.
- laneRenderBatch: 현재 화면 중심에 가까운 LINK부터 정렬하여 MessageChannel 작업당 한 구간씩 생성하고 작업 사이에 화면 처리 기회를 준다. 화면 범위/조건 변경 시 남은 생성 작업을 취소한다. 네이버의 이전 도로 제거는 최대 40개/5ms 배치로 나누고 Leaflet은 canvas를 유지한다. 5ms는 배치 사이의 예산이며 SDK 객체 하나의 처리 시간 상한을 보장하지 않는다.
- incrementalLaneLayer: 화면 이동 시 로딩 중 기존 도로를 유지한다. 조회 완료 후 LINK_ID로 비교하여 겹치는 구간의 지도 객체와 이벤트를 재사용하고, 화면 밖 구간만 제거하며 새 구간만 중심 우선 순서로 추가한다. 차로 선택 해제와 줌 13 미만은 표시를 정리한다. 조회 실패 시 기존 표시를 유지하며 재시도를 제공한다.
- LaneRoadStatus: 차로 안내창에 현재 배율을 함께 표시한다. 네이버는 CSS 반 단계 확대를 반영한 표시 배율을 사용하며 Leaflet은 실제 지도 줌 값을 사용한다. 소수 한 자리까지 표시하고 정수의 불필요한 .0은 생략한다.
- ConnectedCourseControl: MainPage의 distanceRange가 거리의 단일 소유자다. 차로 선택 후 줌 13 이상/현재 범위 조회 완료 때 거리 연결 버튼을 활성화한다. 지도 중심과 가까운 원본 시작 노드에서 선택한 차로의 F_NODE→T_NODE로 경로를 연결한다. 지도 위치만 바뀌면 이전 생성 경로는 유지하며 버튼으로 현재 범위에서 다시 생성한다. 거리/차로/경로 형태가 바뀌거나 차로 안내창이 사라지면 생성 경로와 진행 중 Worker를 정리한다. 계산 실패는 이전 결과를 보존하고 오류를 안내한다. 순환/편도 버튼은 DifficultyControl과 같은 상호 배타 선택 패턴이며 공유 ConnectedCourseControl이 소유한다. locale은 한국어다.
- connected-course: 정적 LINK 부분 그래프만 사용한다. LineString의 구면 거리 합계를 미터로 계산하며 결과 합계가 min/max 안일 때만 반환한다. 방향을 뒤집거나 좌표 교차로 연결을 추측하지 않는다. 불연속 multipart는 제외하며 이음 좌표 간격 60m 초과 경로는 배제한다. 순환 경로는 귀환 시 출발 경로의 내부 노드 재사용을 금지한다. 최대 가까운 8개 시작점/각 64개 반환 후보를 탐색하며 no-match는 해당 제한과 현재 화면 범위의 결과다. 전체 전국 최적 경로 또는 실제 통행 가능성을 보장하지 않는다. 계산은 Worker로 분리하여 지도 조작을 막지 않는다.
- 두 지도 제공자의 독립 표시 레이어: 파랑 도로선, 원본 도로명 또는 이름 없는 도로와 LANES/LINK_ID/노드 정보를 textContent로 제공한다. 기존 빨강 도로/코스 레이어와 분리해 지도 중심을 바꾸지 않는다. 네이버는 확대 raster 화면을 고려해 실제 보이는 bounds로 조회한다.
- 다중 연결 추천: 희망 거리를 최대 3개 거리대로 나누고 다익스트라로 거리대별 1개를 찾는다. 5~10km는 5~6/7~8/9~10km, 10~20km는 10~13/13~16/16~20km다. 폭 5km는 1km 구간 3개, 폭 6~10km는 앞 두 구간을 floor(폭/3)km로 나누며 나머지는 마지막 구간에 둔다. 더 좁은 범위는 소수 한 자리의 3등분, 동일 최소/최대는 하나의 거리대로 처리한다. 못 찾은 거리대는 다른 거리로 채우지 않는다. 내부 거리대는 사용자에게 노출하지 않는다. 선택 버튼은 후보 1·2·3으로 표시하고 결과 문구에 선택 후보의 실제 합산 거리를 표시한다. 안내와 오류에도 거리대 분할 방식을 노출하지 않는다. 선택한 경로만 빨강으로 그린다. 거리대 사이에는 도로 중첩을 허용하되 같은 LINK 집합의 중복 결과는 제외한다. 키보드 Enter와 aria-pressed를 지원하며 실패는 이전 결과를 유지한다.
- DistanceControl: 최소 허용 거리 5km, 최대 30km, 최소·최대 차이는 10km 이하다. 최대를 늘려 폭이 10km를 넘으면 최소를 최대-10으로 이동한다. 최소를 줄여 폭이 10km를 넘으면 최대를 최소+10으로 이동한다. 조절점 순서가 뒤집히면 다른 조절점을 같은 값으로 맞춘다. 숫자 입력과 슬라이더는 distance-range.js의 updateDistanceRange를 공유하며 입력은 정수 km다.
- LaneRoadStatus: 준비/확대 필요/불러오는 중/성공 건수/빈 결과/오류 및 재시도. 바뀐 조건의 이전 선을 즉시 제거하고 늦은 응답이 다시 그리지 못하게 한다.

- 경로 비용: 원본 LANES별 길이 비용 배수는 3/4/5=1, 2/6=1.5, 7=2, 8 이상=2.5, 1 또는 미확인=3이다. 실제 거리는 geometry 미터 합계이며 비용과 분리한다. 진입/진출 도로의 교차점 인근 방위각 차이로 직진(<30도)=0, 우회전=50, 좌회전=150, 유턴(절댓값 150도 이상)=500의 회전 비용을 가산한다. 회전 비용은 실제 주행거리 미터가 아닌 비교용 비용 단위다. 중복 좌표는 건너뛰며 시작 시 회전과 주행 종료 뒤의 가상 회전은 계산하지 않는다. 귀환 경로 탐색에는 출발 경로의 마지막 LINK를 전달해 접합 회전도 반영한다.
- 비용 탐색 상태: 다익스트라 우선순위는 누적 비용이다. 현재 노드와 진입 LINK마다 비용/거리의 비지배 상태를 최대 8개 유지한다(저비용 7개와 최단 거리 상태). 출발점 8개, 편도 128개/순환 64개 후보 제한 안에서 검증된 최저 비용 결과를 거리대별로 선택한다. 더 짧고 비싼 경로도 유지해 저비용 우회가 거리 상한을 초과할 때 대안을 찾는다. 역방향 탐색은 회전 비용 없는 하한으로만 사용한다. 반복 LINK는 배제한다. 상태 수와 후보 제한 때문에 전역 최적 경로를 보장하지 않는다. 실제 교통량·사고 자료 연동은 아직 없으며 통행 제한·보호구역은 비용에 반영하지 않는다.
- 미래 교통량/사고 비용: road-data-cost.js가 선택 차로 LINK의 trafficVolume/LANES와 accidentCount/km를 비교 가능한 집단의 기준으로 정규화해 길이 비례 비용을 가산한다. 자세한 입력 계약은 ROAD-COST-DATA.md를 따른다. 관측값·양수 기준·동일 기간이 있어야 반영하며 없으면 점수 null/추가 비용 0으로 기존 경로 비용을 유지한다. 실제 0과 미관측은 구분하고 costBreakdown/dataCoverage를 제공한다. 현재 실데이터 연동은 없고 사용자 화면에 가짜 지표나 비용 수식을 표시하지 않는다.
