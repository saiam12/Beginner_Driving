# Gemini 맞춤 코스 추천

## 역할과 흐름

연습 목표·회피 상황 → 전체 차로의 실제 LINK에서 후보 풀 생성 → 총 cost 순 상위 3~5개 채택 → 후보별 특징 계산 → 서버에서 Gemini 비교 → 검증한 후보 선택과 근거 표시.

기존 예시 코스 카드에는 연결하지 않는다. 지도 위 실제 도로 후보만 Gemini의 입력이며 새 경로를 생성하거나 지도 좌표를 수정할 권한은 없다. 학습 모델·사전 학습한 사용자 만족도 점수는 아니다.

## 차로와 사용자 선호

- 모든 차로를 읽는다. 선호 차로를 고르면 미선택 차로에 `구간 길이 × 3`를 가산하고 해당 도로를 그래프에서 제외하지 않는다. 모두 해제하면 기본 차로·회전 비용으로 탐색한다. 7+는 원본 7차로 이상이다.
- 기본 차로 비용 배수와 우회전/좌회전/유턴 비용은 유지한다. 좌회전 회피 시 추가 250, 유턴 회피 시 추가 500, 좁은 도로 회피 시 1차로/차로 미확인 구간에 길이 × 1.5를 가산한다. 회피는 절대 금지가 아니다.
- 연습 목표는 Gemini 비교에 전달한다. 운전 경험은 수집하거나 전달하지 않는다. 회피와 선호 차로는 후보 생성에도 전달해 맞는 후보가 생성될 기회를 높인다. 모델이 비용 가중치를 임의로 바꾸지 않는다.
- 길이 제한, 노드 연결, 반복 LINK 배제는 프로그램이 담당한다. 화면 내 도로와 기존 탐색 제한 안에서 후보를 찾으므로 전역 최적·통행 가능·합법 회전을 보장하지 않는다.
- 파란 전체 차로선은 렌더링하지 않는다. 선택한 실제 후보의 빨간 경로만 표시한다. 기존 검색 도로와 예시 지도 기능은 유지한다. 배율 13부터 현재 구역 데이터만 준비하며 128타일/12,000구간 상한은 유지한다.

## Gemini에 전달하는 정보

`src/lib/course-recommendation.js`가 실제 geometry에서 거리, 선호 차로 비율, 1차로 비율, 회전 유형별 횟수를 계산한다. 기존 탐색 비용도 보조 지표로 전달한다. 정확한 위치, 도로명, 전체 geometry, LINK_ID, 사용자 식별자, 자유 입력은 보내지 않는다. 좌회전 등 회전 수는 도로 접합 형상의 추정이며 노드/교차로 수나 실제 신호 수와 다르다.

교통량·사고는 `ROAD-COST-DATA.md`의 입력 계약을 따른다. 길이 가중 정규화 지표, 관측 거리 비율, 기간을 요약한다. **모든 후보가 전체 구간 관측·동일 집계 기간**이어야 해당 항목을 AI 비교와 설명에 허용한다. 서로 다른 집단의 비교 기준이 적합한지는 데이터 병합 단계에서 확인해야 한다. 부분 자료는 기존 구간 cost에는 들어갈 수 있지만 AI 비교에서는 제외한다. 미관측은 `null`, 실제 관측 0은 `0`이다.

## API와 응답 검증

- `api/recommend-courses.js`: Vercel Node 서버 함수. Vite 개발 서버도 같은 handler를 사용한다.
- `server/gemini-recommendation.js`: 서버에서만 키를 읽어 REST `generateContent` 호출. 기본 `gemini-3.8-flash`, `GEMINI_MODEL`로 변경 가능. 모델 접근 권한은 계정별 실제 호출로 확인한다.
- `POST /api/recommend-courses`: 최대 5개 요약과 유효한 선택 조건만 허용. 거리 5~30km, 범위 폭 최대 10km, JSON 16KB 제한. 알 수 없는 속성은 모델 입력에서 제거한다.
- Gemini는 JSON Schema에 따라 `ranking: [{candidateId, evidenceKeys}]`를 반환한다. 모든 기존 후보를 한 번씩 포함해야 하며 유효한 근거 코드 1~3개만 허용한다. 없는 후보, 중복 후보, 없는 교통량/사고 근거, 잘못된 JSON/미완료 응답을 거부한다.
- 설명은 모델의 자유 문장을 그대로 출력하지 않고 검증된 근거 코드와 실제 수치로 생성한다. AI가 고른 순위의 근거 지표를 보여주는 방식이며 학습된 적합도·안전 확률은 표시하지 않는다. 순위가 사용자의 선호를 충분히 반영하는지는 실제 API 및 사용자 평가로 별도 검증한다.
- Gemini 호출당 20초 timeout, 공유 풀 탐색·재선택 예산 70초(결과 기록은 별도), 110초 클라이언트 timeout. 같은 인스턴스에서 1분 10회/IP 및 동시 4회 제한. 이 제한은 분산 서버 전체의 한도가 아니므로 공개 운영 시 호스팅 WAF/인증/프로젝트 할당량과 함께 관리한다.
- 다른 browser origin 거부, 키·제공자 원문 오류 비노출, 응답 캐시 금지. 헤더·입력·출력·키 로그를 저장하지 않는다. 서버는 브라우저가 계산한 요약을 검증하며 원본 geometry를 재조회해 검증하는 기능은 없다.

## 사용자 화면

왼쪽에서 연습 목표에서 주행 목표 하나와 피하고 싶은 상황을 고르고 지도를 확대한 후 `후보 찾기` → `AI 맞춤 추천`을 누른다. API 호출 전 조건과 후보 요약이 Google Gemini에 전달된다는 안내를 표시한다. AI는 추천 후보를 선택하고 `AI 추천` 표시와 비교 지표를 제공한다. 총 cost 순 후보 번호는 유지한다. 다른 후보도 계속 선택할 수 있다.

조건 변경·재계산·지우기·언마운트는 이전 AI 요청을 취소/무시한다. 지도 이동 자체는 현재 후보를 지우거나 AI 재요청하지 않는다. 실패/키 미설정/할당량/응답 검증 실패 시 기존 후보를 보존하고 수동 재시도할 수 있다. 요청은 명시적 버튼으로만 시작한다. 새로고침 시 사용자 조건은 초기화되고 별도 개인정보/평가 DB는 아직 없다.

## 설정

`.env.local`의 기존 지도 설정 아래에 서버 전용 환경변수를 추가한다. 키를 채팅이나 저장소에 넣지 않는다.

```dotenv
GEMINI_API_KEY=발급받은_Gemini_API_키
GEMINI_MODEL=gemini-3.8-flash
```

`npm run dev`는 변경된 로컬 환경변수를 다음 API 요청에 읽는다. 배포 시 Vercel 서버 환경변수에 같은 이름으로 설정하고 재배포해야 한다. `VITE_GEMINI_API_KEY`는 사용하지 않는다. `npm run preview`는 정적 빌드만 제공하며 API를 실행하지 않으므로 개발 서버 또는 Vercel에서 검증한다. 키 없는 상태는 503으로 정직하게 표시하고 가짜 AI 결과로 대체하지 않는다.

## 검증

- `npm run test:connected`: 미선택 차로가 필요한 연결 구간으로 포함되는지, 선호 비용 변화·모두 해제·기존 거리/회전/데이터 비용을 검증.
- `npm run test:lanes`: 전국 실제 타일을 읽어 선택 없는 전체 차로 로딩, 중복·확대 상한·기존 데이터 기능을 검증.
- `npm run test:ai`: 실제 geometry 요약, 기간/관측 범위, 입력/근거/후보 검증, 모의 Gemini REST 성공·실패·timeout, 서버 제한, 브라우저 응답 검증. 실제 Gemini 품질 검증과 다르다.
- `npm run test:ai:live`: 키 설정 후 합성 후보를 Gemini에 실제로 전달해 명확한 회피 선호·응답 구조·없는 데이터 제외를 검증한다. 실제 사용자 평가나 현장 안전 검증은 아니다.

## 공식 근거

- [Gemini 구조화 출력](https://ai.google.dev/gemini-api/docs/generate-content/structured-output): REST generationConfig.responseFormat.text의 JSON Schema 사용.
- [Gemini API 키](https://ai.google.dev/gemini-api/docs/generate-content/api-key): 서버 프록시와 환경변수로 키 보호.

다음 단계는 익명 선택·운전 후 부담도 평가를 수집해 기존 비용 추천 대비 적합도를 평가하는 것이다. 현재 구현에서 사용자 피드백 저장이나 별도 모델 학습은 제공하지 않는다.

## 2026-10-06 후보 풀 변경

현재 화면은 exploreCourseCandidates로 희망 거리 전체 범위를 탐색하고 모든 발견 후보를 cost 순으로 보여준다. 기본 3개, 선택 시 4/5개를 채택하며 AI는 채택한 후보만 비교한다. 기존 거리대별 API connectCourses는 호환성 테스트용으로 유지한다.

총 cost = 차로 + 선호 조건 + 회전 + 교통 + 사고 비용. UI는 반올림해 표시하지만 정렬과 AI 전달에는 원래 실수를 쓴다. km당 cost는 진단용이며 채택 순위를 바꾸지 않는다. 같은 LINK 집합의 회전된 출발점은 중복으로 취급하고 가장 저비용 결과를 남기고 비용이 같으면 지도 중심과 가까운 시작점을 남긴다. 같은 방향의 공통 LINK 길이 / 긴 경로의 길이가 90% 이상인 후보는 낮은 cost 대표만 채택한다. 90% 미만 중첩은 허용한다.

탐색은 지도 범위의 도로, 화면 4×4 구역당 최대 3개의 분산 시작 노드(최대 48개), 시작당 순환 귀환 시도 64개(편도 128개), 진입 LINK당 비지배 상태 8개로 제한한다. 발견된 후보 전체를 표시하는 것이며 모든 가능한 사이클이나 전역 최저 비용 k개를 보장하지 않는다. 정확히 10개를 강제하지 않는다. 귀환은 각 출발 경로에 대한 최저 비용 경로 하나만 검사하므로 거리 하한을 충족하는 다른 귀환 경로를 놓칠 수 있다.

A* 교체는 하지 않았다. 고정된 귀환 목적지의 탐색 최적화에는 검토할 수 있으나 여러 거리 제한 순환 후보 생성은 별도 탐색 전략이 필요하다. 휴리스틱은 남은 실제 비용을 과대평가하지 않도록 검증해야 한다.

변경 검증: 10개 독립 순환 경로의 전체 보존/비용 정렬/동일 경로 중복 제외/상위 3~5개 채택과 5개 Gemini 입력·응답 검증 테스트 통과. 실제 LINK를 읽은 Leaflet 마포구 배율 14 화면에서 4,326구간 → 순환 후보 19개, 첫 후보 5.06km/cost 5,893 확인. 미채택 후보 19(8.40km) 선택 확인. 로컬 모의 Gemini가 채택 5개 중 후보 5를 선택하는 UI 흐름 확인(실제 외부 Gemini 호출 아님). 390×844에서 전체 후보 Enter 선택과 가로 넘침 없음(문서 폭 390, 목록 scrollWidth/clientWidth 228) 확인. 비용 화면 증거는 .local/screenshots/course-cost-pool.png 및 course-cost-pool-mobile.png. 프로덕션 빌드, 정적 UI 감사 통과.

자동 출발점은 화면 안의 노드만 사용하며 직접 출발점을 지정하면 300m 안 가장 가까운 도로 시작 노드 하나로 후보 전체를 고정한다. Gemini에는 기존 후보의 통계 요약만 전달하며 지정 좌표/시작 노드/전체 경로 좌표는 전송하지 않는다. 자동 탐색은 시작점 표본과 기존 탐색 제한을 사용하므로 화면 내 모든 노드의 전역 최적 경로를 보장하지 않는다.

## 기존 key_pool 공유 시트 연결

`server/gemini-key-pool.js`가 Instagram 분석기의 `analyzers/gemini/pool/sheets.py`와 같은 Apps Script 프로토콜을 사용한다. 새 시트나 스크립트 배포를 만들지 않는다.

- `GEMINI_POOL_MODE=sheets`일 때 서버의 `GEMINI_API_KEYS` 별칭과 `GEMINI_MODELS` 조합을 `acquire`에 전달한다. 시트가 잔여량·RPM·사용중 예약을 보고 선택한 키와 모델을 사용한다. 실제 키는 Gemini에만 전달한다.
- `GEMINI_POOL_URL`, `GEMINI_POOL_TOKEN`, `GEMINI_POOL_USER`, `GEMINI_API_KEYS`, `GEMINI_MODELS`는 서버 전용이다. `VITE_` 접두사를 붙이지 않는다. URL은 기존 `script.google.com/macros/s/.../exec` 배포로 제한한다.
- 현재 공유 풀은 3.5/3.6/3.7 Flash만 지원한다. sheets 모드에서는 단일 키의 `GEMINI_MODEL`을 무시한다. 단일 키 방식은 `GEMINI_POOL_MODE=single`을 명시한다.
- 호출 종료 후 `finish`에 예약 ID, 결과 상태, HTTP 오류 코드와 토큰 집계만 기록한다. 코스 요약·정확한 위치·키·인증 토큰을 시트 로그에 기록하지 않는다. 성공 상태는 제공자 응답 수신을 뜻하며 코스 응답 검증 성공과는 구분된다.
- 503 서버 혼잡 시 일시 제한으로 기록하고 같은 요청에서는 해당 모델을 제외해 다른 허용 모델로 재선택한다. 429 시 quotaId에 명시적인 일일 제한이 있을 때만 일일 소진으로 기록한다. 나머지는 일시 제한과 대기 시간으로 기록한 뒤 해당 키·모델 조합을 제외하고 새 예약으로 최대 3회 시도한다.
- acquire/finish의 전송 재시도는 같은 예약 ID를 사용한다. 브라우저 취소 후에도 결과 기록을 시도한다. 공유 풀 오류 시 단일 키로 자동 우회하지 않는다.
- finish가 끝내 실패하면 같은 서버 인스턴스 메모리에 보관하고 다음 요청에서 먼저 재전송한다. 해당 기록을 전송하지 못하면 새 예약을 만들지 않는다. 서버 재시작·서버리스 cold start 후에는 메모리 기록이 없어질 수 있으며, 기존 Apps Script의 10분 lease가 예약 잠금을 복구하지만 토큰/결과 기록은 복구되지 않는다. 영구 결과 기록 보장이 필요하면 별도 durable outbox가 필요하다.
- 키 동기화(sync)는 자동 실행하지 않는다. 기존 분석기 설정의 로컬 키를 사용하므로 공유 키가 추가·교체되면 해당 서버 환경변수도 갱신해야 한다.

이번 로컬 연결은 기존 분석기의 URL/토큰/키/모델 설정을 비공개 `.env.local`로 복사했고 사용자는 기존 별칭 뒤에 `-driving`을 붙여 구분했다. 원본 분석기와 Apps Script 코드는 변경하지 않았다. 배포 서비스에는 같은 서버 환경변수를 별도로 설정하고 재배포해야 한다.

검증: `npm run test:pool`, `npm run test:ai`, `npm run test:ai:live`, `npm run build`.
REST의 responseFormat.text.mimeType은 APPLICATION_JSON enum을 사용한다. 공식 참조: https://ai.google.dev/api/generate-content#TextResponseFormat
