# 차로 수별 실제 도로 표시

상단 우측에 1~6 및 7차로 이상 버튼을 추가했다. 복수 선택, 재클릭 해제, 전체 해제를 지원하며 모바일에서는 검색 아래 같은 버튼을 표시하고 선택 시 지도 보기로 전환한다.

## 데이터

`scripts/preprocess-lane-tiles.py`는 기존 국토교통부/ITS 2026-09-14 `MOCT_LINK.shp`·DBF·PRJ를 읽는다. 원본 도로명 검색의 제외 조건을 사용하지 않으므로 도로명이 없는 구간도 포함한다. 양의 정수 `LANES`가 없거나 형상이 비어 있는 구간은 분류하지 않는다. 차로 수는 원본 LINK 속성 그대로이며 왕복 합계나 추천 난이도를 뜻하지 않는다.

원본 PRJ의 선언 좌표계를 EPSG:4326으로 변환하여 z12 공간 타일로 저장한다. 좌표는 소수 여섯 자리이며 원본 SHP는 수정하지 않는다. 형상 bbox가 걸치는 타일마다 저장해 경계에서 길이 끊기지 않도록 하고, 웹에서는 LINK_ID로 중복을 제거한다. 명칭·차로·LINK_ID·시작/끝 노드를 안전한 텍스트로 표시한다.

`public/data/roads/lanes/manifest.json`에는 차로별 원본 구간 수와 타일 목록이 있고, 각 `{x}/{y}.jsonl.gz`에는 실제 구간이 있다. `.local/roads/lane-tiles`는 배포하지 않는 중간 파일이다. 기존 검색 metadata/geometry는 유지한다.

## 지도와 상태

파란색은 차로 선택으로 표시한 실제 LINK다. 검색한 도로와 예시 코스의 기존 빨간색 표시를 보존한다. 네이버는 기존 raster 확대 배율을 반영한 실제 보이는 범위를 조회한다. Leaflet은 독립 canvas pane으로 그려 기존 선택 경로 아래에 둔다.

줌 13 이상에서 현재 화면의 타일만 불러온다. 13 미만에서는 요청과 표시를 중단한다. 넓은 범위가 128타일 또는 12,000 LINK를 넘으면 임의로 일부만 표시하지 않고 확대 안내한다. 선택 없음, 지도 준비, 확대 필요, 로딩, 성공 건수, 빈 결과, 실패 및 재시도를 제공한다. 화면 이동·조건 변경 시 기존 요청을 취소하며 늦은 결과는 표시하지 않는다. 요청은 최대 6개 병렬, 타일 캐시는 128개다.

도로마다 지도 객체를 동기적으로 한 번에 생성하던 작업을 MessageChannel 작업으로 나눴다. 현재 화면 중심에 가까운 LINK부터 한 작업에 한 구간씩 생성하고, 범위 변경 시 남은 작업을 취소한다. 네이버의 이전 객체 제거도 최대 40개/5ms 배치로 처리해 배경 탭에서도 정리가 멈추지 않도록 한다. 데이터 저장 타일의 z12는 표시 시작 배율 13과 별개다.

## 2026-10-06 희망 거리 연결

### 다중 추천과 빨간 경로

차로·회전 비용 검증: 실제 길이와 비용을 분리했다. 차로 배수는 3/4/5=1, 2/6=1.5, 7=2, 8 이상=2.5, 1/미확인=3이며 직진/우회전/좌회전/유턴 비용은 0/50/150/500이다. 노드+진입 LINK 상태로 회전 비용을 계산하고 비용/거리 비지배 상태를 최대 8개 유지한다. 순환 귀환 시작의 회전도 포함한다. 역방향 그래프는 회전 없는 비용 하한만 제공한다. 현재 화면/가까운 8개 시작점/제한된 후보 중 낮은 비용을 선택하며 전역 최적해는 보장하지 않는다. 사고·교통량·보호구역·통행 규제는 이 비용 변경에 포함하지 않는다.

테스트에서 더 긴 3차로 순환/편도를 짧은 1차로 경로보다 우선하고 실제 거리 상한 초과 대안은 배제함을 확인했다. 회전 방위각, 중복 좌표, 직진·우회전·좌회전·유턴 비용 순서와 우회전 후보 선택도 검증했다. 실제 네이버 마포구 배율 14 / 전체 차로 / 4,288 LINK에서 5~10km 후보 5.06/7.03/9.11km, 후보 2·3 선택과 빨간 경로 전환을 확인했다. 연결 테스트·빌드·strict UI 감사·diff 검사 통과. 화면은 `.local/screenshots/lane-turn-cost-courses.jpg`다.

최신 추가 검증: 같은 마포구 배율 14에서는 10~20km 미발견 안내를 확인했고, 범위를 넓힌 배율 13.5 / 6,490개 LINK에서는 10~13/13~16/16~20km에 각각 11.62/14.47/18.00km 순환 경로가 생성됐다. 390px 모바일에서는 긴 거리대 버튼을 두 열로 배치해 기존 지도 안내 카드를 가리지 않도록 했다. 화면은 `.local/screenshots/distance-bands-long.jpg`, `distance-bands-mobile.jpg`다.

최신 거리대별 추천: 5~10km는 5~6/7~8/9~10km, 10~20km는 10~13/13~16/16~20km로 나누어 거리대별 1개만 탐색한다. 같은 LINK 집합 중복은 제외하지만 서로 다른 거리대의 일부 구간 중첩은 허용한다. 아래 80% 겹침 배제 설명은 이전 구현 기록이다. 현재는 최소 5km, 최대 20km, 범위 폭 최대 10km이며 숫자 입력과 슬라이더가 같은 updateDistanceRange를 사용한다. 범위 초과 시 반대 조절점도 이동한다. 실제 5~15→최대 16 변경 시 6~16, 최소 3 입력 시 5~15, 최대 20 입력 시 10~20 전환과 이전 경로 정리를 확인했다. 마포구 배율 14에서 5~6/7~8/9~10km에 각각 5.49/7.55/9.48km 경로를 확인했다. 거리대별 순환·편도/미발견 생략/동반 이동 전수 조합 테스트, 빌드와 strict UI 감사 통과. 화면은 `.local/screenshots/distance-bands-desktop.jpg`다.

다익스트라로 구한 후보에서 거리 조건과 노드/좌표 연결 검증을 통과한 최대 3개를 반환한다. 공통 LINK의 길이가 짧은 경로 길이의 80% 이상이면 유사 대안으로 제외한다. 순환의 출발 위치만 바뀐 동일 경로도 제외하며 후보가 부족하면 발견한 개수만 보여준다. 번호/거리 버튼으로 하나를 선택하면 해당 경로만 빨간색(#dc2626)으로 표시한다. 기본 선택은 첫 번째이며 기존 차로선과 예시 코스는 보존한다.

실제 네이버 마포구 배율 14 / 1·2차로 / 5~10km에서 순환 8.43·7.55·7.45km, 편도 7.49·7.52·7.63km의 각 3개 후보를 확인했다. 버튼 클릭과 Enter로 경로 2·3 전환, 형태 변경 시 초기화, 결과 지우기를 확인했다. 390px 모바일에서 버튼 줄바꿈과 거리/결과 표시를 확인했다. 연결 테스트(3개 순환/편도, 거리 합산, 연결성, 중복·80% 겹침 배제, 단일 순환의 1개 반환), 빌드, strict UI 감사 및 diff 검사 통과. 검증 화면은 `.local/screenshots/connected-courses-desktop.jpg`와 `connected-courses-mobile.jpg`다. 기존 보라색 경로 검증 기록은 이전 구현의 결과다.

기존 희망 거리 입력을 실제 LINK 연결에도 적용했다. 현재 화면에 로딩된 선택 차로의 F_NODE→T_NODE 방향으로만 연결하며, LINK 형상의 지표면 거리를 합산한다. 순환은 출발 노드로 돌아오는 별도 복귀 경로, 편도는 서로 다른 출발·도착 경로다. 교차하는 선이나 가까운 끝점을 임의로 연결하지 않는다. 계산은 Worker에서 수행하고 표시 결과는 보라색이다. 거리·차로·형태 변경은 기존 결과와 진행 중 계산을 취소한다.
